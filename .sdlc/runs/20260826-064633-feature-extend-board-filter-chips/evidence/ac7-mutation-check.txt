--- F1 REGRESSION CAUGHT BY THE NEW WIRING MODEL, 2026-08-26 ---
The first URL-authoritative implementation WAS WRONG and its own new test caught it.

Failing output before the correction:
  × still restores from localStorage when the URL carries no filters
      Expected: [ "label-bug" ]   Received: null
  × treats ?status= as no filters, so the restore is not suppressed
  Test Files 1 failed (1) | Tests 2 failed | 12 passed (14)

Cause: on mount the sync-down effect runs AFTER the localStorage-restore effect
has already queued its state update, so the functional updater's `prev` was the
restored filters (not the all-null default). With an empty URL,
boardFilterSearchMatches({}, restored) is false, so it overwrote the restore with
defaults - silently breaking AC-3.

Correction: skip the effect's first invocation via hasSyncedFromUrlRef. Mount
precedence stays with the seed/restore path; only post-mount URL changes are
adopted. All 14 pass after the fix.
