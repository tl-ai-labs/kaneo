## Feature scope — modules a per-column WIP limit would touch

Identified from **source files only**. Kaneo's board "lanes" are the `column` entity; there is no separate lane concept.

### 1. Database schema (the one editable schema file)

- `apps/api/src/database/schema.ts` — `columnTable` at **line 342**. Existing shape: `id, projectId, name, slug, position, icon, color, isFinal, createdAt, updatedAt`. A nullable `wipLimit: integer("wip_limit")` fits the existing `integer(...)` idiom already used by `position`. Nullable is the right default for an *advisory* limit — null means "no limit", which avoids a backfill on existing installs.
- `apps/api/drizzle/` — 43 existing migrations. The new one must be **generated**, not written: `pnpm --filter @kaneo/api db:generate`, then inspect the SQL and commit it with the schema change. This directory is off-limits to direct authoring but the generated file is expected output.
- `apps/api/src/database/relations.ts` — unchanged; a scalar column adds no relations.

### 2. API routes and validators

- `apps/api/src/column/index.ts` (175 lines) — all five column routes with inline Valibot validators and `describeRoute` OpenAPI metadata. Two validators need `wipLimit`:
  - `POST /:projectId` create validator, **line 56-64**
  - `PUT /:id` update validator, **line 132-140** — use `v.optional(v.nullable(v.number()))` to mirror how `icon`/`color` model "clearable" fields; `isFinal` uses plain optional boolean and is the wrong template for a nullable field.
  - Authorization is already correct via `workspaceAccess.fromColumn("id")` + `requireWorkspacePermission({ project: ["update"] })`. **No new permission vocabulary needed** — editing a WIP limit is a project-update operation, same as renaming a column.

### 3. API controllers

- `apps/api/src/column/controllers/update-column.ts` (41 lines) — the `data` param type and the conditional `.set({...})` spread at **line 25-30** both need a `wipLimit` branch. The `data.x !== undefined && { x: data.x }` pattern is the local idiom; it correctly lets `null` through as an explicit clear.
- `apps/api/src/column/controllers/create-column.ts` (87 lines) — accept and persist an initial value.
- `apps/api/src/column/controllers/get-columns.ts` (15 lines) — plain `select()`, so it picks up the new field for free.

### 4. The projection gotcha — load-bearing

- `apps/api/src/task/controllers/get-tasks.ts`, **lines 224-237**. This is what actually feeds the kanban board, and it **hand-whitelists** column fields rather than spreading the row:

  ```ts
  const columns = projectColumns.map((column) => ({
    id: column.slug,
    slug: column.slug,
    name: column.name,
    icon: column.icon,
    isFinal: column.isFinal,
    tasks: /* ... */,
  }));
  ```

  A `wipLimit` added to the schema **will not reach the board UI** unless it is added here explicitly. (Note `color` is already silently dropped by this same projection — evidence the omission is easy to make.) Also note `id` is set to `column.slug` in this projection, which is why `ColumnHeader` passes `column.id` as a task `status`.

### 5. Typed client and web data layer

- `packages/libs` — the typed Hono client is **inferred**, no hand edit needed, but `pnpm typecheck` across consumers is the real proof the contract propagated.
- `apps/web/src/types/project/index.ts` — `ProjectWithTasks` derives its `columns` element type from `InferResponseType` of the tasks endpoint. Flows automatically **once step 4 is done**; stays silently absent if step 4 is missed.
- `apps/web/src/fetchers/column/update-column.ts` (25 lines) — duplicated inline `data` type must gain `wipLimit`.
- `apps/web/src/hooks/mutations/column/use-update-column.ts` (34 lines) — a **third** copy of the same `data` shape, at the `mutationFn` param. Already invalidates both `["columns", projectId]` and `["tasks", projectId]`, which is exactly what a WIP-limit change needs since the count lives on the tasks query.
- `apps/web/src/fetchers/column/create-column.ts` and `use-create-column.ts` — same treatment if the limit is settable at creation.
- `apps/web/src/hooks/queries/column/use-get-columns.ts` — read path, likely no change.

### 6. Kanban column header (the over-cap indicator)
