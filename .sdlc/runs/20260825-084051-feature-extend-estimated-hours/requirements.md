# Requirements — feature-extend — Estimated hours on tasks with per-lane rollup

Run: `20260825-084051-feature-extend-estimated-hours` · Intent: `feature-extend` · Policy: `opus-only-v5`
Base: `feature-extend-2/opus-only` @ `5d1fc910` · Form: **delta requirements** (Intent matrix, brownfield)

This is a *delta* document. It states only what changes relative to the code at `5d1fc910`.
Everything not named here is required to behave exactly as it does today.

---

## 1. In scope

1. A nullable `estimatedMinutes` integer column on `taskTable`, with a drizzle-kit generated
   migration (`0043_*`) that is additive and safe on an existing populated database.
2. A dedicated task API endpoint that sets, changes, and clears a task's estimate, gated by the
   existing `task: ["update"]` workspace permission.
3. Valibot validation of the estimate on that endpoint: integer, `0 < n <= UPPER_BOUND`, or `null`
   to clear. Invalid input returns 4xx, never 500.
4. `estimatedMinutes` returned by both task read projections (`getTask`, `getTasks`) and declared
   on `taskSchema` so the OpenAPI response metadata stays accurate.
5. A new estimate popover under `apps/web/src/components/task/`, registered in all three responsive
   variants of `task-properties-sidebar.tsx` (compact, mobile, desktop).
6. Hours-in / minutes-stored conversion at the UI boundary: the user types hours (`2.5`), the API
   stores minutes (`150`); display renders minutes back as hours.
7. A small badge on the kanban `task-card.tsx`, rendered only when the task has an estimate.
8. A per-lane rollup in `column/column-header.tsx` showing the summed estimate of that lane's tasks,
   rendering **nothing at all** when no task in the lane has an estimate.
9. Static i18n keys for all new user-facing copy, added to `i18n/en-US.json` (source of truth) and
   propagated to all 17 other locales so `pnpm i18n:check` stays green.
10. Focused tests: API-side validation/normalization (DB-free, `tests/api/**`), web-side estimate
    formatting/parsing, card badge visibility, and lane rollup at zero / one / several estimates.
11. **Import/export round-trip** (added at Gate 1, OQ-1): `export-tasks.ts` emits `estimatedMinutes`
    and `import-tasks.ts` accepts it, so an export -> import cycle preserves estimates including the
    `null` case, covered by a round-trip test.

## 2. Out of scope (this run)

1. No link to `timeEntryTable` tracked time; no estimate-vs-actual comparison anywhere.
2. No estimate field in the create-task modal.
3. No project-, workspace- or board-level totals outside the lane header.
4. No estimate history, activity type, notification, or webhook payload change.
5. No changes to gitea/github sync, MCP tools, or the published `packages/mcp` surface.
6. ~~Import/export round-trip.~~ **Moved INTO scope at Gate 1** (OQ-1 answered `yes`). See §1.11,
   FR-30/FR-31 and AC-14. The verified finding that motivated the move: `export-tasks.ts` projects an
   explicit field list (`title, description, status, priority, dueDate, startDate, userId, labels`)
   and would otherwise have silently dropped the estimate.
7. No sorting or filtering of tasks by estimate (`get-tasks.ts` `sortBy` union is untouched).
8. **No estimate on the full-task `PUT /task/:id` body — this is deliberate, not an oversight.**
   Confirmed by the user at Gate 1 (OQ-2). That route's `.set()` does not mention
   `estimatedMinutes`, so an existing full-update **preserves** the stored estimate rather than
   clearing it. This includes the column-header "archive all" path, which calls `useUpdateTask` once
   per task: archiving a lane does not wipe its estimates. A later reader must not "fix" this
   omission by adding the field to that body — preserve-by-omission is the chosen behaviour, on the
   grounds that it is the smaller diff and the safer default. Covered by AC-15.

## 3. Functional requirements

### Module: API — persistence

- **FR-1** `taskTable` gains `estimatedMinutes: integer("estimated_minutes")`, nullable, no default.
  NULL is the only representation of "no estimate"; `0` is not a valid stored value.
- **FR-2** The migration is generated by `pnpm --filter @kaneo/api db:generate` against this
  branch's journal (next index `0043`), producing exactly one `ALTER TABLE "task" ADD COLUMN
  "estimated_minutes" integer;`, plus the drizzle snapshot and `_journal.json` entry.
  Adding a nullable column with no default is a metadata-only change in PostgreSQL — no table
  rewrite, no lock escalation risk on a populated `task` table.
- **FR-3** No index is added. The lane rollup is computed client-side from tasks already loaded for
  the board; there is no query that filters or orders by `estimated_minutes`.

### Module: API — validation

- **FR-4** A DB-free module `apps/api/src/task/estimated-minutes.ts` exports the bound constant and
  a normalizer that maps a raw request value to `number | null`, throwing `HTTPException(400)` with
  a descriptive message on anything invalid. It must not import `../database` (so it stays
  importable from the DB-free `tests/api` suite).
- **FR-5** Accepted: an integer `1..MAX_ESTIMATED_MINUTES`, and `null`. Rejected with 400:
  `0`, negatives, non-integers (`90.5`), `NaN`, `Infinity`, values above the bound, and
  non-numeric types.
- **FR-6** `MAX_ESTIMATED_MINUTES = 60 * 24 * 365` (525,600 minutes = 8,760 h = one year).
  Chosen so a per-lane sum of a realistically large lane cannot approach `Number.MAX_SAFE_INTEGER`
  or PostgreSQL `integer` overflow (2,147,483,647): 4,084 fully-maxed tasks in one lane would be
  needed to overflow int32, which is not reachable on a rendered board.
- **FR-7** The route-level Valibot validator declares the field's shape (`v.optional(v.nullable(
  v.number()))`) so a wrong *type* is rejected by the framework as 400 before the handler runs;
  the normalizer in FR-4 enforces the *value* rules and produces the human-readable message.

### Module: API — routes and controllers

- **FR-8** New route `PUT /task/estimate/:id`, modelled exactly on the existing
  `PUT /task/due-date/:id`: `describeRoute` with `operationId: "updateTaskEstimate"`,
  `tags: ["Tasks"]`, a `resolver(taskSchema)` 200 response, then
  `validator("param")` → `validator("json")` → `workspaceAccess.fromTask()` →
  `requireWorkspacePermission({ task: ["update"] })` → `requireEntitlement` → thin handler.
- **FR-9** The handler stays thin: parse, normalize via FR-4, delegate to a new controller
  `apps/api/src/task/controllers/update-task-estimate.ts`, return `c.json(task)`.
- **FR-10** The controller loads the task (404 `HTTPException` if absent), updates
  `estimatedMinutes`, returns the updated row, and throws 500 only on a failed write — matching
  `update-task-due-date.ts`'s shape.
- **FR-11** **No `publishEvent` call.** The estimate produces no activity entry, notification, or
  integration side effect this run (§2.4), and there is no existing activity `type` in
  `activitySchema`'s picklist that fits. Adding one would require a schema/enum change that is
  explicitly out of scope. This is a deliberate deviation from the due-date controller and must be
  recorded as such in the design.
- **FR-12** `getTask` and `getTasks` add `estimatedMinutes: taskTable.estimatedMinutes` to their
  select projections, so the board and the task detail both receive it.
- **FR-13** `taskSchema` in `apps/api/src/schemas.ts` gains
  `estimatedMinutes: v.nullish(v.number())`, keeping the OpenAPI response contract accurate for
  every route that resolves `taskSchema`.

### Module: API — import / export (added at Gate 1, OQ-1)

- **FR-30** `export-tasks.ts` adds `estimatedMinutes` to its select projection and to the emitted
  per-task object, passing the stored integer through unchanged (`null` stays `null`).
- **FR-31** `import-tasks.ts` accepts an optional `estimatedMinutes` on each imported task and
  writes it to the inserted row. An absent or `null` field imports as `null`. An invalid value
  follows the importer's existing coercion posture rather than aborting the whole import: it is
  coerced to `null` and reported through the importer's existing warning channel if one is
  available, otherwise coerced silently — an import must not 500 on one bad estimate.
- **FR-32** The round-trip is lossless for valid data: exporting a project whose tasks carry
  `[150, null, 90]` and re-importing the payload yields tasks carrying `[150, null, 90]`.

### Module: API — authorization

- **FR-14** Setting or clearing an estimate requires the same workspace permission that already
  gates task updates (`requireWorkspacePermission({ task: ["update"] })`), enforced in the API.
  The UI capability check is an affordance, not the control.
- **FR-15** `workspaceAccess.fromTask()` runs before the permission check, so a task in a workspace
  the caller cannot see resolves to the existing not-found/forbidden behavior unchanged.

### Module: Web — data plumbing

- **FR-16** `Task` (`apps/web/src/types/task/index.ts`) gains `estimatedMinutes: number | null`.
- **FR-17** New fetcher `apps/web/src/fetchers/task/update-task-estimate.ts` using the typed
  `client` from `@kaneo/libs` — no parallel untyped request layer.
- **FR-18** New mutation hook `apps/web/src/hooks/mutations/task/use-update-task-estimate.ts`,
  invalidating the same query keys as `use-update-task-due-date.ts` (`task`, `tasks`, `projects`,
  `activities`) so the card badge and the lane rollup both refresh after a change.

### Module: Web — conversion and formatting

- **FR-19** A DB-free, dependency-free module exports:
  - `parseEstimateHours(input: string): number | null | "invalid"` — trims, accepts an empty string
    as `null` (clear), accepts `2`, `2.5`, `0.25`, rejects `0`, negatives, non-numerics, and values
    above the API bound. Rounds hours→minutes with `Math.round` so `0.1 h` → `6 min` exactly.
  - `formatEstimateHours(minutes: number | null | undefined): string | null` — `null`/`undefined`
    → `null`; `150` → `"2.5h"`; `120` → `"2h"` (no trailing `.0`); `90` → `"1.5h"`; `20` → `"0.33h"`
    (at most 2 decimal places, trailing zeros stripped).
- **FR-20** `sumEstimatedMinutes(tasks): number | null` returns `null` when **no** task in the list
  has a non-null estimate, and the integer sum otherwise. `null` — not `0` — is what makes the lane
  header render nothing. A lane whose tasks all have `null` is indistinguishable from an empty lane
  for rollup purposes, which is the required behavior.

### Module: Web — edit surface

- **FR-21** `TaskEstimatePopover` in `apps/web/src/components/task/`, following the
  `task-due-date-popover.tsx` contract exactly: `{ task, children }` props, `PopoverTrigger asChild`
  wrapping `children`, `useWorkspacePermission().canUpdateTasks()` guard that returns
  `<>{children}</>` unchanged when the user cannot edit, `toast.success` / `toast.error` on the
  mutation, `setOpen(false)` on success.
- **FR-22** The popover contains a number input pre-filled with the current estimate in hours, a
  save action, and a clear action shown only when an estimate is set. Invalid input surfaces an
  inline validation message and does not dispatch the mutation.
- **FR-23** The popover is registered in **all three** responsive variants of
  `task-properties-sidebar.tsx` (compact ~L141, mobile ~L333, desktop ~L521), each using the same
  ghost-button trigger shape as the adjacent start-date/due-date triggers, showing the formatted
  estimate when set and a muted placeholder label when not.

### Module: Web — board display

- **FR-24** `task-card.tsx` renders an estimate badge in the existing badge row (the
  `flex items-center gap-1.5` container that already holds the priority and due-date badges),
  visually consistent with the neighbouring `inline-flex items-center gap-1 rounded border
  border-border/70 bg-muted/55 px-2 py-1 text-[10px]` badge. Rendered only when
  `formatEstimateHours(task.estimatedMinutes)` is non-null. When unset, the card's DOM is byte-for-
  byte what it is today.
- **FR-25** `column/column-header.tsx` renders the lane rollup next to the existing task-count
  chip, in the same chip style, only when `sumEstimatedMinutes(column.tasks)` is non-null. When
  null, **no element is rendered at all** — not an empty span, not a zero.
- **FR-26** The rollup sums only the tasks the column already holds (`column.tasks`); it introduces
  no new query, no new request, and no new re-render trigger beyond the existing project store.

### Module: i18n

- **FR-27** New keys live under the existing `tasks` namespace, alongside their siblings:
  `tasks.properties.estimate`, `tasks.properties.noEstimate`,
  `tasks.popover.estimate.{title,placeholder,save,clear,invalid,updateSuccess,updateError}`,
  `tasks.kanban.laneEstimate` (accessible label/title for the rollup chip).
- **FR-28** `i18n/en-US.json` is the source of truth. All **16** other locale files carry the same new
  keys (English placeholders, Gate 1 OQ-3) so this run introduces no new `i18n:check` complaint.
  (`i18n/` holds 17 locale files + a generated `schema.json`; the earlier "17 other locales" was an
  off-by-one that counted `schema.json` as a locale.)
- **FR-33** `i18n/schema.json` is **regenerated** via `pnpm i18n:schema` after `en-US.json` changes.
  It is generated from `en-US` with `additionalProperties: false` and an explicit `required` list at
  every level, so skipping this step leaves every locale file invalid against its own schema.
  Never hand-edited. See change_plan.md §16 C-2.
- **FR-29** No user-facing string is hardcoded in a component. The `"h"` unit suffix produced by
  `formatEstimateHours` is a symbol shared across the supported locales and is treated as
  formatting, not copy; if the reviewer disagrees it becomes a key.

## 4. Non-functional requirements

- **NFR-1 — Compatibility.** Every existing task row has `estimated_minutes = NULL` after the
  migration. Existing cards, lane headers, sidebars, API responses, and the OpenAPI document must
  be observably unchanged for those rows.
- **NFR-2 — Performance.** The rollup is `O(tasks in lane)` over an array already in memory, run
  during the column header's existing render. No added network calls, no added query keys, no added
  effects. This matters on task-heavy boards (AGENTS.md, "Protect performance").
- **NFR-3 — Simplicity.** One column, one endpoint, one popover, one badge, one rollup. No new
  permission vocabulary, no new table, no new event type.
- **NFR-4 — Conventions.** Thin Hono handlers; domain behavior in a controller; Valibot validation;
  `HTTPException` for expected failures; `requireWorkspacePermission`; fetchers under
  `apps/web/src/fetchers/`; server state in TanStack Query hooks; typed `@kaneo/libs` client;
  inferred types and `type` over `interface`.
- **NFR-5 — Migration safety.** Generated by drizzle-kit, inspected before acceptance, additive
  only. `pnpm exec biome format --write` is applied to the generated snapshot and journal
  afterwards (drizzle-kit emits 2-space JSON; committed snapshots are tab-indented) — this is the
  approved sequence, not a hand edit.
- **NFR-6 — Verification hygiene.** `pnpm exec biome ci .` is already red on this branch for
  reasons unrelated to this run. Verification uses `pnpm exec biome check <changed paths>` only.
  `biome.json` and `.gitignore` are off-limits.
- **NFR-7 — Write contract.** Every write lands inside the frozen allowlist in
  `.sdlc/local/write-contract.json`. Notably `apps/web/src/lib/**` is **not** allowlisted, so the
  formatting helpers of FR-19/FR-20 are colocated inside the allowlisted component directories
  rather than in `lib/`. This is a contract-driven placement and is recorded in the design.

**Two precision corrections made after the security review (S-1, S-3).** The original wording said
"not emitted to events" and "not exposed via MCP". Both were literally wrong as shipped, though both
have nil exposure:

- **Events.** The import path's `publishEvent("task.created", { ...createdTask })`
  (`import-tasks.ts`) spreads the inserted row, which now carries `estimatedMinutes`, into the
  **in-process** event payload. Every consumer projects explicit fields — the WebSocket layer
  forwards only `{projectId, taskId, type}`, the generic webhook sends only
  `title/description/priority/status/number`, and activity/notification destructure named fields —
  so the value never leaves the process. The guarantee is restated above as *outbound*, so a future
  consumer that spreads `data` does not inherit a false promise.
- **MCP.** No MCP tool changed, but `list_tasks` and `get_task` are thin proxies that return the
  task read's JSON body verbatim, so the field does appear in their output. The proxy carries the
  caller's own token through the same `workspaceAccess` checks — same data, same principal, no new
  MCP capability and no boundary crossed.

**Known OpenAPI drift (S-2, informational).** `taskSchema` now declares `estimatedMinutes` as a
required member, and `apps/api/src/search/index.ts` documents its response as `v.array(taskSchema)`
while `global-search.ts` projects an explicit field list that omits it. `resolver()` is
documentation-only so there is no runtime effect, and the schema was *already* misaligned with the
search response for `position`, `number` and `description` — this widens a pre-existing inaccuracy
rather than creating one. Recorded, not fixed: fixing it means giving search its own response schema,
which is outside this ticket.

## 8. Gate 1 resolutions — all five settled, none open

Approved `2026-08-25`. These are decisions of record; the design and every packet must honour them.

### OQ-1 — Import/export round-trip → **IN SCOPE**
`export-tasks.ts` projects an explicit field list and would have silently dropped the estimate.
Both files already sit inside the allowlisted `apps/api/src/task/**`, so no write-contract change
was needed. Implemented as FR-30/FR-31/FR-32, verified by AC-14, which must include the `null` case.
Rationale of record: *a documented data-loss path is worse than ten lines of scope.*

### OQ-2 — Full-update `PUT /task/:id` → **LEAVE ALONE**
Preserve-by-omission is the chosen behaviour. Recorded explicitly in §2.8 and AC-15 so that a later
reader does not mistake the omission for an oversight and "fix" it.

### OQ-3 — Translations → **ENGLISH PLACEHOLDERS via `pnpm i18n:check:fix`**
The model must **not** author translations into the other 17 locales. Two reasons of record:
(a) `i18n:check:fix` is the repo's own intended workflow; (b) nobody in this session can review
`zh-CN` or `el-GR`, so machine-authored strings would ship unverified.

> **Guard requirement (binding).** `--fix` will happily backfill *unrelated* pre-existing missing
> keys into every locale. The run must therefore: capture the pre-run state of the locale files,
> run the fix, and then verify that each locale's diff contains **nothing but this feature's keys**,
> reverting any unrelated backfill. AC-16 is this guard.

### OQ-4 — Executable authorization test → **NO, DO NOT WIDEN THE ALLOWLIST**
Authorization on `PUT /task/estimate/:id` stays verified by **inspection** (AC-4), not by an
executing test. `tests/api-integration/**` remains outside the write contract, and no unrunnable
test is to be staged anywhere.

**This is a deliberate choice with a stated cost, not an environmental limitation.** Unlike the
earlier benchmark arms, this branch has a fresh, empty database (`kaneo_opus_only`) and a real
integration test *could* have run here. The user chose consistency across the benchmark over taking
that opportunity.

The cost, which the final report must state plainly: **no executed test covers the middleware chain
on `PUT /task/estimate/:id`.** A regression that dropped `requireWorkspacePermission({ task:
["update"] })` from that route would pass every check this run performs — typecheck, biome, API
unit tests, and web tests alike.

### OQ-5 — Activity event → **OMIT `publishEvent`**
Confirmed: `activitySchema`'s `type` is a closed picklist — `comment`, `task`, `status_changed`,
`priority_changed`, `unassigned`, `assignee_changed`, `due_date_changed`, `title_changed`,
`description_changed`, `create` — with no estimate-shaped member. Publishing would mean widening a
closed schema, which is beyond the brief.

Consequences of record, both of which the final report must state:
1. **The lane rollup is not realtime for other viewers.** A teammate with the board open sees the
   old lane total until their next refetch. The editing client is correct immediately because its
   mutation hook invalidates the `tasks` query key (FR-18).
2. **This diverges from every sibling single-field update controller.** `due-date`, `priority`,
   `title` and `assignee` all publish an event; `estimate` alone does not.

## 9. Decisions carried forward unchanged from the Gate 1 proposal

Restated because the design and the packets depend on them:

1. **Dedicated endpoint** `PUT /task/estimate/:id`, modelled on `PUT /task/due-date/:id` — not a
   widening of the full-update body.
2. **`MAX_ESTIMATED_MINUTES = 525_600`** (one year), sized so a per-lane sum cannot approach int32
   overflow.
3. **`null`, not `0`, is the rollup's empty signal.** `sumEstimatedMinutes` returns `null` when no
   task in the lane carries an estimate; that `null` is what makes the header render nothing.
4. **Helpers colocated in the allowlisted component trees.** `apps/web/src/lib/**` is outside the
   write contract and must not be reached for. NFR-7 stands.

## 10. Standing run constraints (in force through Gate 4)

- **Benchmark isolation.** Nothing may be read from or copied out of sibling branches: no
  `git show` / `checkout <ref>` / `diff <branch>` / `merge` / `restore --source`, no reading other
  branches' `.sdlc/runs/*` leftovers on disk, and no reading the stale `dist/` build artifacts that
  contain a sibling's compiled version of this exact feature. Every line is written fresh
  against `5d1fc910`.
- **Database is `kaneo_opus_only`** — fresh and empty. Never `kaneo`, which is one migration ahead
  from a sibling branch.
- **Verification is scoped**: `pnpm exec biome check <changed paths>`. `pnpm exec biome ci .` is
  pre-existing red on this branch; it must not be fixed here, and must not be attributed to this run.
  `biome.json` and `.gitignore` are off-limits.
- **No commit, no push, no PR.** Never `pnpm lint` (it runs `biome check --write .` and rewrites
  unrelated files).
- **`claude-cli` ignores declared output ceilings.** `budget.maxOutputTokens` is recorded to
  telemetry as `ceiling_used` but never reaches the process; `hard_cost_cap_usd: 50` is the only
  real backstop, so packets are sized deliberately.
